# 2026-10-15 角色皮肤与模板素材依赖审查

本次核对国服 3.3.0 / Unity 2022 配表、Toys 现有角色皮肤接口与本地 Addressables 资源；不启动、不修改游戏。卡牌 SkinManager / ConfigCatalog 不在本次修改范围。

## 已证实并修复

### 角色模板遗漏安装内置 Addressables 目录

- 位置：`src/AstralParty.Toys/Services/CharacterBundleCatalog.cs` 构造函数的资源根目录枚举。
- 原实现只扫描 `*_Data/StreamingAssets/aa` 和传入的下载缓存。当前游戏还把资源放在 `AstralParty_CN_Data/com.unity.addressables/AssetBundles/`。
- 实际接口探针使用 `catalog_3.3.0.json`，修复前 `Resolve(["GameData_CN"])` 为空，修复后正确命中安装目录的 `be8a6f7fa87357b26096b5a0ada25e0b/10381fc5c55c7b0896a3a91a257cc9ce/__data`。
- 影响：`CharacterTemplateExporter` 无法定位新位置中的配置/角色资源，可能使用随包配表回退或在导出时报告资源缺失；即使资源实际已随游戏安装，也无法找到。
- 修复：保留旧布局与缓存，同时扫描 `*_Data/com.unity.addressables`。
- 独立回归：`CharacterBundleCatalogTests` 用最小 Addressables catalog 分别验证旧/新安装布局，不依赖真实游戏。

### 新皮肤仍使用旧静态尺寸表

- 位置：`src/AstralParty.Toys/Services/CharacterImageSize.cs:35` 查询内嵌 `Resources/Skins/character-image-sizes.json`，未命中时所有非地图图片回退为 1024×1024。
- 实际影响：`HybridWindow.CharacterSkins.cs:197` 把该尺寸传给裁剪，保存时按此宽高渲染；新立绘、窄图等会套用方形尺寸，不能保留原图比例。
- 已定位的新皮肤：113 / 100113006（资源后缀 113_04）、117 / 100117006（117_04）、119 / 100119005（119_03）。这些资源在当前本地 catalog 中都能解析。
- 最初核对立绘/头像/窄图等六类字段发现 17 个缺项；扩展到这三套皮肤的全部资源字段后，共有 39 个真实 Texture2D 键缺少尺寸。
- 修复：通过 Toys 自己的 `CharacterBundleCatalog` 和 `CharacterUnityResources` 只读加载本地 bundle，读取 Texture2D 的 `m_Name`、`m_Width`、`m_Height`，将 39 个真实尺寸追加到静态表，保留全部旧项。
- 例：113_04 立绘 1416×1612；117_04 普通/SFW 立绘 1261×2048；119_03 普通/SFW 立绘 1857×2048；三者头像均 220×220、窄图 128×308，半身图 1568×900。
- 独立回归：`CharacterNewSkinImageSizeTests` 验证三个皮肤全部非空图片槽位均命中真实尺寸，并检查立绘、头像、窄图的具体宽高。
